# 0.9 · 움직임 추정과 광학 효과

후속 사용자 결과: 0.9.3에서 끊김, 중간 반전의 다른 화면 비율 노출, 끝점 블러의 급격한 해제가 보고됐습니다. 시각적 연속성 검증을 통과한 버전이 아닙니다. 후속 수정은 [0.10 화면 인계](smooth-handoff-0.10.md)에 기록합니다.

사용자가 깜빡임 해결을 수용한 0.8.3/0.8.4 이후의 별도 개선입니다. 2026-09-11 사용자는 정밀 센서 접근 제한을 설명받고, 오차가 있는 자이로 추정 시험판을 허용했습니다. 다른 작업의 구현은 사용하지 않았습니다.

## 달라진 동작

- `FoldOptics`: 진행 값에 따라 외부 오른쪽의 효과 범위가 넓어지고, 내부 왼쪽의 효과가 걷힙니다. 경계 위치·폭·확산 반경·음영을 따로 계산합니다.
- `FoldRenderer`: 원본 해상도를 보존하며 두 단계 Gaussian 확산과 영역별 음영을 GPU에서 합성합니다. 정지한 오른쪽 영역에 추가 원근 왜곡이나 흐림을 넣지 않습니다.
- `MotionAngleEstimator`: 공개 3단계 신호 사이에서 주 자이로 Y축 회전을 적분합니다. 정지 시 재생 시간이 흘러 효과가 진행되지 않고, 회전 방향이 바뀌면 현재 값에서 되돌아갑니다. 센서 간격이 120ms보다 길면 해당 구간의 적분을 버립니다.
- 0.9.1은 추정 방향 반전으로 논리 화면 크기도 바꿨지만 사용자가 화면이 튀는 회귀를 보고했습니다. 0.9.2에서 이 경로를 제거했습니다. 추정값은 광학 효과에만 쓰고 실제 화면 전환은 기존 공개 접힘 신호로 결정합니다.
- 완전히 접거나 펼친 공개 신호로 드리프트를 초기화합니다. 끝점의 100ms 광학 정리와 기존 앱 프레임 인계는 유지합니다.

`StableDisplay`, `PanelPower`, `RecoveryGuard`, `NativeScene`, 화면 캡처와 입력 전달 구조는 0.8.4 경로를 유지했습니다. 5분 시험·잠금/화면 공유 종료 시 정리도 유지합니다.

## 실제 입력의 한계

이 모델의 공개 힌지 이벤트는 0/90/180 세 값입니다. Samsung Folding Angle 센서와 보조 IMU는 SSENSOR 시스템 권한이 필요합니다. 서비스 메타데이터와 공개 진단을 추가 확인했지만 정상 권한으로 사용할 수 있는 연속 각도 getter는 찾지 못했습니다. 보호된 센서의 값을 우회해 읽지 않았습니다.

사용자가 직접 3회 왕복한 자이로 측정에서 펼침 Y축 적분은 +6.5/+35.1/+33.3°, 접힘은 −22.5/−54.5/−64.6°였습니다. 힌지의 180°와 다른 값입니다. 충분히 큰 표본의 중앙값으로 펼침 5.2694, 접힘 3.3043을 사용합니다. 손의 움직임과 기기 전체 회전이 바뀌면 추정 오차가 커집니다. 센서가 있는 쪽을 고정하면 반응이 약할 수 있습니다. 이 방식의 정확도를 ±몇 도로 보장할 수 없습니다.

재현: `python3 tools/motion_calibration.py measurements/motion-calibration/raw.jsonl OUTPUT.json`. 보정 파일은 기기 앱 내부 `files/motion-calibration.json`에 저장합니다. 이 파일이 없으면 3단계 효과로 동작하며 자이로 추정은 사용하지 않습니다.

## 확인한 범위

- 빌드, Java 단위 테스트 24개, 기존 Python 테스트 7개, Android lint 통과.
- 실제 기기의 GPU 미리보기에서 0/45/90/135/180° 입력을 확인.
- 135° 유지 및 180→135° 복귀의 효과 영역 픽셀 차이 0.
- 내부 오른쪽 영역은 0°와 180° 사이 픽셀 차이 0.
- 실제 접기/펴기 시험 중 연속적인 추정값과 중간 방향 반전 기록을 확보. 센서 추정치의 진짜 물리 각도 오차 측정은 아님.

근거: `measurements/motion-calibration/`, `measurements/native-v23-run/`. 녹화는 진단용 축소본이며 앱의 표시 버퍼는 원본 크기입니다. 최초 내부 녹화는 0바이트로 실패했으므로 해당 시도를 검증 성공으로 세지 않습니다. 실제 육안 결과는 사용자 회신과 함께 판단합니다.

## 0.9.2 추가 사항

사용자가 기기를 눕히는 정도에 따른 위아래 음영과 화면 내용의 미세한 이동을 요청했습니다. 일반 중력 센서의 Z축 크기로 수평 정도를 읽고 위·아래 가장자리에 음영을 추가했습니다. 기기 Y축 중력 성분으로 위아래 비중을 조정합니다. 화면 내용은 움직이는 영역만 약 1~2% 이내로 재배치하며, 물리 경계와 정지한 영역은 고정합니다. 완전 접힘/펼침의 주 화면에는 이동·음영이 남지 않습니다.

0.9.2 빌드·26개 Java 테스트·lint 통과. 실기 수동 미리보기에서 눕힘을 증가시키면 내부 오른쪽 상단·하단은 어두워지고 중앙 표본 영역은 RGB 픽셀 평균까지 동일함을 확인했습니다. 이는 수동 기울기 렌더링 확인이며 실제 접기 전환의 회귀 해소는 별도 사용자 확인 중입니다.

0.9.1 외부 녹화의 1,631개 프레임에서 전체 검정 기준에 해당하는 표본은 없었지만, 사용자는 다른 비율의 화면이 순간 보이는 깜빡임을 보고했습니다. 전체 검정 검사만으로 시각적 연속성을 통과 처리하지 않습니다.

## 0.9.3 프레임 보호

잘못된 종횡비가 선명해질 수 있는 별도 경로를 확인했습니다. 자이로 추정값이 끝점에 먼저 도달하더라도 보조 패널의 비트맵 크기가 해당 패널의 원본 크기와 다르면 균일한 확산을 유지합니다. 프레임 인계에서는 새 레이아웃이 대부분 섞인 뒤 가림을 해제합니다. 이는 다른 앱의 두 레이아웃을 동시에 렌더링하는 기능이 아닙니다. 맞는 레이아웃을 준비하는 짧은 구간은 강하게 확산된 내용으로 표시합니다.

0.9.3 빌드·26개 Java 테스트·lint 통과. 설치 APK는 `artifacts/poldy-0.9.3-depth-optics.apk`입니다. 실기 전환과 육안 결과를 분리해서 기록합니다.

0.9.3 자동 전환 검증: {"errors": [], "transitions": 5, "ready_ms": [353, 422, 357, 377, 390], "inner": {"frames": 223, "full_black_samples": 0}, "outer": {"frames": 183, "full_black_samples": 0}}
이 검사는 기기를 실제로 접지 않고 논리 화면 크기를 왕복시킨 검사입니다. 실제 손으로 접을 때의 시각적 회귀 해소는 아직 사용자 확인 전입니다.

추가로 0.9.3의 실제 접기/펴기 중 YouTube 화면을 포함한 내부 패널 녹화를 확보했습니다. 644프레임에 전체 검정 표본은 없었고, 준비 후 넓은 앱 배치가 선명해지는 것을 표본 프레임에서 확인했습니다. 다른 비율이 순간 보이는 모든 현상 및 주관적 자연스러움이 해결됐다는 판정은 아직 하지 않습니다. 근거: `measurements/native-v25-run/physical-inner.mp4`, `physical-inner-luma.json`, `physical-frames/contact.jpg`.
