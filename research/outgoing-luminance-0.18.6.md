# 0.18.6: 전환하는 쪽 패널의 검은 깜빡임 재진단

후속 작업: [0.19 연속 수집·기울기 효과](continuous-motion-0.19.md). 아래 300초 제한과 표본 유효기간은 0.18.6 당시의 상태입니다.

2026-09-14 macOS, SM-F971N / R5KL8036E1D. 0.18.5(68)에서 원인을 확인한 뒤
0.18.6(69)을 설치했고 사용자가 실기 접힘에서 상당한 개선을 확인했다.

## 재현

사용자는 0.18.5에서 두 번 왕복한 후, 펼칠 때 외부 화면에서, 접을 때 내부
화면에서 검게 꺼지는 모습을 확인했다. 전환 직전까지 보고 있던 물리 패널이다.

`measurements/flicker-20260914-baseline/live-logcat.txt`에서 SurfaceFlinger에
전달된 해당 패널의 출력 밝기가 -1 또는 0으로 내려간 후 다시 양수가 된다.

- 펼침 외부: 10:35:29.415 ~ 29.583, 밝기 복귀까지 약 168ms.
- 접힘 내부: 10:35:32.095 ~ 32.224, 약 129ms.
- 앞선 접힘 내부: 10:35:26.522 ~ 26.715, 약 193ms.

이는 물리 출력에 전달된 값의 시간 간격이다. 고속 카메라로 측정한 발광 시간이나
검정 영상 프레임 수와 동일한 지표가 아니다. `dark-intervals.json`은 비활성
패널의 정상 소등도 포함하므로 그 목록 전체를 깜빡임으로 세면 안 된다.

0.18.5는 패널의 ON 상태만 고정한다. DisplayPowerController가 프로필을 바꾸며
내리는 밝기는 막지 못한다. 따라서 README의 기존 '깜빡임을 막는다'는 표현을
현재 버전의 검증 완료 근거로 사용하면 안 된다.

## 기존 밝기 제어가 실패한 이유

실기 `BrightnessUnitProbe`에서 논리 밝기는 약 0.77, 단위 2의 밝기는 약 358nit다.
동일 수준의 SurfaceFlinger backlight 값은 약 0.15로 단위가 다르다.
2인자 setDisplayBrightness에 논리 밝기를 직접 전달하는 것은 올바른 변환이 아니다.

기기 services.jar의 LocalDisplayAdapter.BacklightAdapter.setBacklight 호출은
5인자 API에 SDR backlight, SDR nits, display backlight, display nits를 전달한다.
이전 0.18.4는 두 backlight에 -1을 전달했으며, 이 펌웨어에서 이는 '유지'가
아니라 OFF를 나타낸다. 메타데이터만 지정해 유지하는 방법으로 사용할 수 없다.

추가로 DisplayDeviceConfig를 별도 shell 프로세스에서 생성해 변환을 읽었으나
시스템 서버의 실제 보정 리소스가 적용되지 않아 nits=-1의 기본 매핑이 반환됐다.
`DisplayCurveProbe` 결과를 실제 패널 보정식으로 사용하지 않았다.

## 수정안

- SurfaceFlinger의 두 물리 패널 출력 기록만 읽어 최근 정상 SDR 값을 보관한다.
- 전환 직전 현재 패널과 current nits가 일치하는 경우에만 해당 물리 패널의
  backlight/nits 값을 반복한다. -1/0, 다른 패널, 오래된 표본, 밝기 불일치,
  HDR처럼 두 nits 값이 다른 표본은 거부한다.
- 밝기 유지 대상은 전환 직전에 보고 있던 패널 하나다. 들어오는 패널은 기존
  시스템 밝기 정책을 따른다. 두 패널의 전원 유지는 기존 구조를 유지한다.
- 밝기 반복은 private shield 동안만, 최대 1.5초다. 일반 Settings 밝기나
  자동 밝기 모드는 기록하지 않는다. 새로운 밝기 수준을 계산하지 않는다.
- 출력 반복의 종료를 패널별 lock으로 확인한 뒤 정상 경로로 복귀한다. 종료 뒤
  뒤늦은 ON/밝기 호출이 시스템 소등과 경쟁하는 일을 막는다.

표본을 얻지 못하면 밝기 유지는 적용하지 않고 기존 전원 유지로 동작한다.
따라서 이 시험판도 모든 조건의 무깜빡임을 보장하지 않는다. 광학 효과와 힌지
보간은 변경하지 않았다. HAL/밝기 기록의 300초 제한은 이번 수정 범위에 남는다.

## 현재 검증

- Java 79개 테스트 통과, Lint 및 APK 빌드 통과.
- 파서 테스트: 실제 epoch 로그, OFF/0 배제, HDR 배제, 다른 패널·오래된 표본·
  현재 밝기 불일치 배제.
- `MeasuredLuminanceTrial`: 프로필/설정 변경 없이 현재 출력만 0.5초 재전달하는
  도구. 처음 시도는 유효 표본 없이 중단됐고 쓰기는 수행하지 않았다. 잠금 해제
  뒤에도 최근 5,000줄 제한이 정지 화면의 마지막 밝기 기록을 놓치는 문제를 확인해,
  SurfaceFlinger로 한정한 기존 버퍼를 읽도록 바꿨다. 표본의 5분 유효기간과
  현재 nits 일치 조건은 유지했다.
- 잠금 해제 후 57회 재전달 성공. backlight=0.152313,
  출력 nits=378.581146, 재전달 뒤 시스템 nits=378.5812였다.
  `measured-luminance-replay-ready.txt`, `replay-ready-surface.txt`에 보관했다.
  정지 화면의 단위/호출 검증이며 접힘 중 무깜빡임의 증거는 아니다.
- 0.18.6 APK는 `artifacts/poldy-0.18.6-luminance-trial.apk`에 준비했다.
- Windows 설치본과 Mac 빌드의 서명이 달라 덮어 설치할 수 없었다. 앱 데이터
  31개 항목은 `measurements/flicker-20260914-baseline/before-mac-reinstall/app-data.tar`
  에 백업하고 tar 읽기를 확인했다. 기존 설치 APK도 같은 폴더에 보관했다.
  0.18.6 설치와 앱 데이터 복원을 완료했고 Shizuku를 다시 연결했다.
- 11:00:45경 0.18.6 실행. `measurements/flicker-20260914-v69/live-logcat.txt`
  수집 구간에는 실제 전환이 없었다. 따라서 이 파일로 개선 수치를 산출하지 않는다.
- 이후 사용자가 "밝기가 튀는 현상이랑 검은 깜빡임 현상은 많이 줄은거 같아.
  아주 가끔 검은 깜빡임 현상이 발생되기는 한데 일단은 괜찮아"라고 확인했다.
  육안 개선은 확인됐고 잔여 깜빡임은 후속 항목으로 남긴다.

## 다음 작업 우선순위

1. 각도/밝기 로그 수집의 300초 제한을 정상 사용 중 끊김 없이 갱신한다.
   서비스의 잠금·중지·비정상 종료 복구와 독립 임대 제한은 유지한다.
   정지 화면에서 오래된 밝기 표본을 재검증하는 방법도 함께 다룬다.
2. 현재 빈 FoldRenderer.attitude/orientation을 구현해 실제 힌지 각도와 별도로
   자이로·중력 방향에 따라 얕은 내용 이동, 반사·음영이 보정되도록 한다.
   과도한 사다리꼴 투영을 다시 도입하지 않는다.
3. 전달한 세 영상과 비교해 블러의 시작·범위·끝점, 부드러운 암부 경계,
   중간 정지·반전에서의 연결성을 조정한다.
4. 홈/다른 앱/가로 영상/잠금 재개/중지 복구와 장시간 배터리·발열을 확인한다.

현재는 다음 기능으로 넘어가도 된다는 사용자 피드백을 받은 상태다.
잔여 깜빡임의 발생 조건, HDR, 자동/수동 밝기, 빠른 반전의 검증은 남아 있다.
