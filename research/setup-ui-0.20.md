# Foldy 설정 화면 · 0.20.1

2026-09-14, macOS에서 개발. APK 버전 0.20.1 / versionCode 74.

## 확인한 화면과 적용 범위

- 연결된 SM-F971N에서 **토스 5.274.1**을 직접 열어 홈, 전체 메뉴, 설정 화면을 확인했다. 큰 광고 문구보다 기능명과 값이 우선하며, 설정 목록은 일정한 행 높이와 좌우 정렬을 반복한다. 메뉴 이동만 수행했고 계정 설정이나 금융 작업은 수행하지 않았다. 임시 참고 스크린샷은 확인 후 삭제했다. 개인 정보가 포함된 화면은 이 저장소나 비교 이미지에 넣지 않았다.
- 아이폰 앱을 직접 실행할 환경은 없었다. Apple 지원 문서의 **iOS 17 ‘디스플레이 및 밝기’ 실제 화면 이미지**를 확인했다. 위쪽 미리보기, 흰색 그룹 안의 설정 행, 그룹 밖의 보조 설명을 참고했다. 최신 iOS 앱을 직접 조작해 검증했다는 의미는 아니다.
- 공개 TDS 문서에서 일반 제목 22/31, 작은 제목 20/29, 본문 17/25.5, 작은 본문 15/22.5의 글자 크기/줄 높이를 확인했다. 아래 Foldy 수치는 이 체계와 실제 화면 관찰을 바탕으로 결정한 값이며, 토스 앱의 내부 스타일을 추출한 값은 아니다.

## 화면 구성

‘접는 순간까지, 매끄럽게’ 등의 홍보 문구와 큰 3단계 진행 표시를 제거했다. 화면은 **기능명 → 조작 가능한 미리보기 → 설정 목록** 순서로 배치한다. 작은 화면은 세로로, 760dp 이상 화면은 미리보기와 설정을 좌우로 배치한다. 내용은 상단부터 시작하며 세로 중앙 정렬로 빈 공간을 늘리지 않는다.

| 항목 | 적용 값 |
| --- | --- |
| 앱 이름 | Foldy, 20sp / 600 |
| 화면 제목 | 24sp / 600, 줄 높이 약 33sp |
| 설정 항목 | 17sp / 400, 줄 높이 25.5sp |
| 본문 | 15sp / 400, 줄 높이 22.5sp |
| 상태·보조 설명 | 13–14sp / 400 |
| 글꼴 | Pretendard Variable 1.3.9, 앱에 포함 |
| 화면 좌우 여백 | 20dp |
| 목록 내부 좌우 여백 | 16dp |
| 설정 행 | 최소 56dp, 큰 글씨에서는 늘어남 |
| 그룹 모서리 | 20dp |
| 하단 버튼 | 최소 54dp, 모서리 14dp |
| 화면 최대 너비 | 세로 560dp / 넓은 화면 1040dp |

글자 크기는 sp로 적용하며 시스템 글자 확대를 따른다. Pretendard의 SIL Open Font License와 저작권 고지를 `app/src/main/assets/licenses/Pretendard-LICENSE.txt`에 함께 포함했다. 토스 전용 글꼴이나 Apple SF Symbols는 사용하지 않는다.

앱 표시 이름, 알림 이름, Gradle 프로젝트 이름, README를 Foldy로 수정했다. 기존 설치와 Shizuku 권한을 이어 쓰기 위해 Android applicationId `dev.poldy.lab`와 과거 로그 태그는 유지한다. 이전 측정·APK 파일명도 기록 보존을 위해 바꾸지 않는다.

## 동작과 상태

- 미리보기의 3D 폴더블 모델은 앱에서 생성한 샘플 화면을 사용한다. 슬라이더와 재생 버튼으로 조작하며 실제 패널을 바꾸지 않는다.
- 미리보기 내부의 흐림·명암에는 기존 `FoldRenderer` / `FoldOptics`를 사용한다. 미리보기의 모델 회전은 실제 화면에 추가 원근을 적용하는 기능이 아니다.
- 첫 진입과 단계 변경 때 각각 1회만 재생한다. 미리보기 자동재생을 끌 수 있고, ‘동작 간소화’와 시스템 애니메이션 비활성화를 존중한다. 화면을 떠나거나 설정 시트를 열면 재생을 멈춘다.
- 시작 단계는 `미리보기 → 화면 제어 연결 → 애니메이션 켜기`다. 이미 연결된 경우 연결 단계를 반복하지 않는다.
- 연결 성공은 실제 Shizuku 사용자 서비스가 READY를 반환해야 표시한다. 재생 시간 경과만으로 완료 상태를 만들지 않는다.
- 실제 서비스 실행 후 올바른 해상도의 첫 프레임을 확보해야 ‘사용 중’이 된다. 이를 위해 서비스에 읽기용 `prepared` 상태를 추가했다. 잠금·종료 때 초기화한다.
- 알림 권한 결과를 기다린 뒤 서비스를 시작한다. 알림을 거부해도 이미 허용된 화면 제어를 사용할 수 있으며 권한을 매번 다시 요청하지 않는다.
- 미리보기 설정의 자동재생·햅틱·동작 간소화는 저장 후 다음 실행에 유지된다. 실제 물리 패널의 접힘 효과 강도 설정은 아니다.

0.19.2의 밝기 복구, 화면 전환, 힌지 측정과 렌더링 로직을 이 UI 작업에서 다시 조정하지 않았다. 남은 드문 깜빡임·밝기 변동이 해결됐다는 추가 주장은 하지 않는다.

## 검증

- Java 단위 테스트 **99개 통과**. 실행 중이어도 화면 연결이 끊기면 성공 상태를 표시하지 않는 사례 포함.
- Android lint **0 errors, 42 warnings**. 주로 기존 코드의 리소스·버전 관련 경고와 Java UI 문자열 지역화 경고가 남아 있다.
- `assembleDebug`, `assembleDebugAndroidTest` 성공.
- UI 전용 instrumentation은 실제 서비스를 켜지 않고 표시 상태만 주입한다. 5가지 단계, 권한 거부 안내, 동작 간소화, 설정 시트의 스크린샷과 하단 버튼의 가시성/활성 상태를 확인했다.
- 360×800dp, 넓은 화면 1088×821dp, 360×800dp 다크 모드/글씨 1.5배에서 각각 8개 화면을 검사했다. 작은 화면과 큰 글씨에서 넘치는 목록은 스크롤되며 기본 버튼은 화면에 유지된다.
- 측정 파일은 `measurements/setup-ui-0.20.1/`에 있다. 이 폴더는 Git에서 제외된다.
- 실제 휴대전화에 `adb install -r`로 0.20.1을 설치하고 화면 제어 연결 성공을 확인했다. 실제 첫 프레임 준비 후 ‘사용 중’이 표시되고, 중지 후 ‘꺼짐’과 다시 켜기 버튼으로 복귀하는 것도 확인했다. 확인 후 애니메이션을 다시 켜 두었다.
