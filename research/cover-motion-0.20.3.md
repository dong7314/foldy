# 펼침 시작 시 외부 화면 정지 · 0.20.3

2026-09-14, SM-F971N / Android 17. 0.20.1에서 사용자가 외부 화면의 펼침 애니메이션이 부자연스럽다고 보고한 뒤 조사했다.

## 확인한 원인

기존 실제 전환 로그에서 내부 화면의 GPU 보관 프레임을 준비하는 동안 외부 화면의 시각 각도가 고정되는 구간을 확인했다.

| 시작 시각 | 측정 각도 변화 | 고정된 시각 각도 | 보관 프레임 준비 시간 |
| --- | --- | --- | --- |
| 13:49:26.070 | 6° → 16° | 1.006° | 180ms |
| 13:49:34.730 | 8° → 13° | 1.694° | 102ms |

`FoldService.renderNow()`의 최상위 조건에 `snapshotPending`이 포함되어, 대상 패널의 GPU 작업을 기다리는 동안 소스 패널 렌더링과 `AngleSmoother.step()`까지 중단했다. 새 힌지 측정값은 수신되지만 효과가 진행되지 않는 코드 경로다. 이는 시작 지연의 확인된 원인이며, 사용자에게 보인 모든 부자연스러움의 원인이라는 뜻은 아니다.

원본 로그는 Git 제외 경로 `measurements/cover-opening-0.20.1/before.log`에 있다. 이후 150초 수집한 `live.log`에는 새 접힘 동작이 들어오지 않아, 해당 파일을 재현 증거로 사용하지 않았다.

## 수정

- 대상 보관 프레임 준비 중에도 각도 보간과 기울기 갱신을 계속한다.
- 현재 패널과 대상 패널이 다르고 현재 패널의 검증된 원본 프레임이 있을 때, 현재 패널만 프레임 주기에 맞춰 계속 그린다.
- 준비 중인 대상 버퍼는 덮어쓰지 않는다. 중간에 되접어 현재 패널 자체가 대상이 된 경우에도 보관 프레임을 보호한다.
- 두 패널 표시 완료, 전환 세대 확인, 대상 해상도의 새 프레임 2장 확인 이후에만 화면을 넘기는 기존 조건을 유지한다.
- 첫 준비 중 렌더 시점과 보관 프레임 완료 시 렌더 횟수·시각 각도를 로그에 남긴다.

## 검증

- 단위 검사 101개 통과. 180ms 보관 프레임 지연 중에도 소스 효과가 진행하면서 대상 프레임 공개는 차단되는 경우를 펼침·접힘 양방향으로 검사했다.
- 같은 패널로 방향을 되돌릴 때 준비 버퍼와 전환 세대가 보호되는 회귀 검사 통과.
- Android lint: 오류 0개, 경고 42개. 앱 APK와 계측 검사 APK 빌드 성공.
- 0.20.2를 설치해 실제 펼침·되접힘 기록을 확보했다. 14:00:43.217에는 내부 보관 프레임이 준비되기 전부터 외부 패널 프레임을 그렸고, 준비 완료 때 시각 각도가 0.266°에서 1.998°로 진행했다. 이 전환의 준비 시간은 38ms였으므로 이전 180ms 기록과 동일 조건의 성능 비교로 보지는 않는다.

## 되접힘 중 추가로 확인한 경합

같은 0.20.2 실기 기록에서 약 30°까지 펼쳤다가 닫는 동안, `DisplayControl`의 CLOSED 복구 감시자가 이전 내부 화면 프로필을 복원하려고 했다. 내부 출력 공개를 마친 직후여서 `switching.pending=false`였고, 실제 패널은 이미 외부로 바뀌어 있었다. 감시자는 이를 예외로 처리해 `reset()`을 호출했다. 다음 외부 전환의 두 패널 표시 완료 기록이 14:00:44.701에 있었지만, 감시자에서 시작한 초기화가 14:00:45.255에 완료됐다. 이어 잠금에 따라 앱 파이프라인이 일시 정지했다.

0.20.3에서는 보호된 전환 밖에서 이전 프로필로 되돌리려는 감시자 요청을 `WAIT_COVER`로 보류한다. 정상적인 다음 전환이 두 패널 표시를 확인하고 새 세대로 화면을 변경하게 한다. 기존 화면 레이어와 임대를 삭제하지 않으며, 같은 프로필의 재확인과 이미 보호 중인 프로필 복구는 유지한다. 세대가 지난 요청 거부 및 시간 제한은 유지한다.

- 최종 단위 검사 **104개 통과**, lint 오류 0개·경고 42개, 앱·계측 APK 빌드 성공.
- 감시자 보류가 세대를 초기화하지 않는지, 다음 전환이 기존 시간 장벽을 지키는지, 같은 패널·보호 중 복구와 초기화 후 정책을 검사했다.
- 0.20.3의 되접힘 경합 수정에 대한 실기 재시험과 최종 사용자 체감 확인은 아직 필요하다.
- 휴대전화에 0.20.3 설치 성공과 패키지 버전 76을 확인했다. 사용자 잠금 해제 후 화면 제어를 연결하고 애니메이션을 다시 실행했다. 14:05:10에는 원본 외부 해상도 1248×1972의 GPU 프레임을 확보했고 서비스 실행을 확인했다. 수정 후 전환 로그는 `measurements/cover-opening-0.20.3/live.log`에 수집한다.
