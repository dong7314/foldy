# Foldy

Foldy는 폴더블 휴대전화가 접히거나 펼쳐질 때 외부 화면과 내부 화면 사이의 전환을 자연스럽게 이어 주는 Android 앱입니다. 화면 구성이 바뀌는 짧은 시간 동안 두 패널을 미리 준비하고, 현재 화면을 각 패널의 원본 해상도로 유지하면서 실제 경첩 각도에 맞춘 흐림과 명암 효과를 적용합니다.

현재 소스와 실기 설치본은 **0.21.3 (versionCode 80) 시험판**이며 Samsung SM-F971N과 Android 17에서 개발하고 있습니다. 0.18.6에서 사용자가 확인한 깜빡임 개선을 유지하면서 수집의 5분 제한을 없애고, 자이로·중력 방향에 따른 작은 내용 이동과 부드러운 음영, 더 이른 블러 시작을 추가했습니다. 0.19.0의 6분 30초 연속 수집, 0.19.1의 실제 GPU·앱 강제 종료 복구 검증을 마쳤습니다. 0.19.1에서 애니메이션·잠금 재개에 대한 사용자 확인을 받았고, 남은 밝기 출렁임을 줄이기 위해 0.19.2는 정상 자동 밝기 대신 순간 OFF만 복구합니다. 일상 사용 시험과 사용자 체감 확인은 [연속 수집과 기울기 효과](research/continuous-motion-0.19.md)에 기록합니다.

검은 깜빡임은 0.18.6에서 많이 줄었다는 사용자 확인을 받았으며, 드물게 남는 현상까지 완전히 제거됐다는 뜻은 아닙니다. 원인과 밝기 유지 방법은 [출력 밝기 재진단](research/outgoing-luminance-0.18.6.md)에 있습니다.

0.20.1은 실제 토스 앱 홈·설정 화면과 Apple의 설정 화면을 참고해 앱 내부 UI를 다시 구성했습니다. 단계별 접힘 미리보기, 그룹 설정 목록, Pretendard 글꼴, 큰 글씨·다크 모드를 지원합니다. [화면 조사와 검증 기록](research/setup-ui-0.20.md)을 참고하세요.

0.20.3은 대상 화면의 보관 프레임을 준비하는 동안 현재 화면의 효과까지 멈추던 경로와, 되접힘 중 시스템 상태 복구가 다음 전환을 초기화하던 경합을 수정했습니다. 실제 펼침·접힘에서의 체감 확인은 진행 중입니다. [외부 화면 정지 원인과 수정](research/cover-motion-0.20.3.md)에 기록합니다.

0.21.0은 대상 패널을 준비하는 동안 효과까지 굳어 있던 보관 이미지를 원본 이미지로 바꾸고, 대기·전환·되접힘 구간에 동일한 각도 효과를 매 프레임 적용합니다. 보호 창에서는 효과와 수집을 중단하고 캐시를 폐기하며, 일반 화면으로 돌아오면 자동 재개합니다. [보안 보강과 접힘 전환 검증](research/privacy-closing-0.21.md)을 참고하세요.

0.21.1은 실제 펼침 시험에서 시스템의 전원 전환 레이어를 보안 창으로 오인해 일시 정지되던 문제를 수정했습니다. 사용자는 접을 때 효과가 한꺼번에 몰려 움직이는 현상이 많이 줄었다고 확인했습니다. 0.21.2는 같은 렌더러를 유지하고, 잠금 해제 뒤 첫 프레임보다 접힘 신호가 먼저 들어오는 경합을 추가로 보완합니다.

0.21.3은 앱 아이콘과 설정 화면 로고에서 왼쪽 도형의 왼쪽 위·아래, 오른쪽 도형의 오른쪽 위·아래 모서리만 살짝 둥글게 다듬었습니다. 가운데 접힘 형태와 색상은 유지합니다. 벡터 미리보기와 APK 빌드로 확인했습니다.

같은 0.21.3 소스로 별도 배포 키를 사용한 비디버그 APK를 만들었습니다. 파일은 `dist/foldy-0.21.3/foldy-0.21.3-release.apk`이며, [설치·업데이트·서명 키 보관 안내](RELEASE.md)와 [배포 빌드 검증 기록](research/release-0.21.3.md)을 참고하세요. 연결된 휴대전화의 개발용 앱은 유지했습니다. 배포용 APK는 가상 기기에서 설치·실행을 확인했으며, 이 서명으로 교체한 실기 접힘 시험과 스토어 등록은 아직 진행하지 않았습니다.

저장소에는 검증한 [0.21.3 배포용 APK](artifacts/releases/foldy-0.21.3/foldy-0.21.3-release.apk)와 [SHA-256 체크섬](artifacts/releases/foldy-0.21.3/SHA256SUMS)을 별도로 보관합니다. 배포 키와 개인 측정 자료는 포함하지 않습니다.

## 주요 기능

- 외부 1248×1972, 내부 2448×1848 패널을 각각 원본 해상도로 준비합니다.
- 화면 전환 전에 현재 패널의 프레임을 유지하고, 대상 앱이 새 화면 크기로 배치된 뒤 시스템 출력으로 복귀합니다.
- Samsung HAL에서 읽은 1–179° 경첩 각도를 보간해 효과가 손의 움직임을 따라가도록 합니다. 로그 수집은 정상 사용 중 자동으로 갱신됩니다.
- 자이로와 중력 방향으로 흐림의 분포·음영·얕은 내용 이동을 보정합니다. 힌지 각도는 자이로로 추정하지 않습니다.
- 두 물리 패널의 전원을 전환 중 잠시 유지합니다. 밝기 하강으로 생기는 검은 깜빡임은 별도로 수정·검증 중입니다.
- Apple iPhone Duo 제품 뷰어의 Wipe 재질을 분석한 내부·외부 방향별 확산, 명암, 화면 밝기 곡선을 적용합니다.
- 화면 비율이 다를 때 내용을 자르거나 늘이지 않고 패널 안에 맞춥니다.
- 화면 잠금, 앱 중지와 비정상 종료에서 임시 장치 상태와 패널 출력을 시스템 정책으로 복구합니다.

## 동작 방식

Foldy는 Shizuku 사용자 서비스를 통해 시스템 화면을 GPU 버퍼로 받고, Foldy 자체 레이어는 다음 캡처에서 제외합니다. Android 화면 공유나 화면 녹화 권한은 요청하지 않습니다. 화면 전환 동안 `SurfaceControl` 레이어로 양쪽 패널의 마지막 정상 프레임을 유지한 뒤 대상 해상도의 새 프레임이 준비되면 실제 앱 화면을 다시 드러냅니다.

렌더러는 웹용 3D 기기의 원근을 화면에 다시 투영하지 않습니다. 물리 패널 자체가 이미 접히므로 소프트웨어 원근을 중복 적용하면 외부 화면이 찌그러지고 검은 쐐기가 생깁니다. 현재 구현은 실제 패널 위에 Wipe 기반 확산과 명암을 합성하고 기울기에 따른 작은 내용 이동을 더합니다. 이동은 화면 폭의 0.4%, 높이의 0.5% 이내이며, 빈틈이 생기지 않도록 소폭 확대합니다. 보이는 끝점에서는 추가 이동·확대·블러가 정확히 0입니다.

핵심 흐름은 다음과 같습니다.

```text
HAL 경첩 각도
  → 각도 보간
  → 양쪽 패널 프레임 유지
  → 대상 디스플레이 프로필 전환
  → 대상 원본 해상도 프레임 확인
  → Apple Wipe 기반 GPU 합성
  → 시스템 출력 복귀
```

## 요구 사항

- Samsung SM-F971N
- Android 17 기반의 현재 검증 펌웨어
- Shizuku 13.6 이상
- 빌드 시 Android SDK 36과 JDK 17

루팅, 부트로더 해제, 펌웨어 수정은 필요하지 않습니다. 시스템 내부 API와 기기별 디스플레이 구성을 사용하므로 다른 모델이나 펌웨어에서는 자동 제어를 활성화하지 않습니다.

## 사용 방법

1. Foldy에서 미리보기 각도를 조절하고 **설정 시작하기**를 누릅니다.
2. Shizuku를 실행한 뒤 **화면 제어 연결**을 눌러 접근을 허용합니다.
3. **애니메이션 켜기**를 누릅니다.
4. 다른 앱을 사용하면서 휴대전화를 접거나 펼칩니다.
5. Foldy 화면에서 **애니메이션 끄기**, 또는 알림에서 **중지**를 누르면 원래 화면 상태로 복구됩니다.

5분 뒤 자동 종료되는 시험 제한은 없습니다. 화면 잠금 중에는 수집과 패널 제어를 해제하고, 잠금 해제 후 다시 준비합니다. 각 로그 자식 프로세스는 300초로 제한하되 정상 서비스가 다음 프로세스를 시작하므로 앱 종료 뒤 무기한 남지 않습니다.

Shizuku는 일반적으로 휴대전화를 재부팅한 뒤 다시 시작해야 합니다. 설정 방법은 [Shizuku 공식 안내](https://shizuku.rikka.app/guide/setup/)를 참고하세요.

## 빌드와 검증

Windows PowerShell:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
./gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
python -m unittest discover -s tools -p 'test_*.py'
```

macOS 또는 Linux:

```sh
export JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home'
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
python3 -m unittest discover -s tools -p 'test_*.py'
```

빌드 결과는 `app/build/outputs/apk/debug/app-debug.apk`에 생성됩니다. `src/test`는 상태 전환, 프레임 소유권, 각도와 광학 곡선을 검증하며 `src/androidTest`는 실제 Android GPU에서 렌더 경계와 성능을 검사합니다. 이 검증 코드는 배포 APK에 포함되지 않습니다.

## 프로젝트 구조

- `app/src/main`: 앱 UI, 포그라운드 서비스, Shizuku 디스플레이 제어, GPU 렌더러
- `app/src/test`: JVM 단위 테스트
- `app/src/androidTest`: Android GPU 계측 테스트
- `research`: 기기 동작, 깜빡임 원인, 참고 애니메이션 분석 자료
- `tools`: ADB 수집, 영상 분석, 기기별 재현과 검증 도구
- `artifacts`: 실기 검증에 사용한 버전별 APK와 체크섬

구현 근거는 [검은 깜빡임 조사](research/black-flash-investigation.md), [네이티브 화면 인계](research/native-handoff-0.14.2.md), [전원·밝기 유지와 공식 모션](research/power-pin-apple-motion-0.15.md), [Apple Wipe 재질 분석](research/apple-wipe-material-0.16.md)에 기록했습니다. 공식 제품 뷰어에서 추출한 61개 각도 표본은 [apple-duo-slider-profile.json](research/apple-duo-slider-profile.json)에 보관합니다.

## 개인정보와 제한 사항

화면 프레임은 기기 메모리에서만 처리하며 저장하거나 전송하지 않습니다. 앱에는 네트워크 권한이 없습니다. 보호 콘텐츠와 보안 콘텐츠는 Android의 캡처 정책에 따라 가려집니다.

Foldy가 요청하는 사용자 승인은 알림과 Shizuku 접근입니다. Shizuku 연결 중에는 검증된 SM-F971N에서만 접힘 전환용 장치 상태 요청, 패널 전원 임대, 물리 출력 경로와 패널별 회전 정책을 제어합니다. 장치 상태 요청은 전환 뒤 취소되고, 전원 임대는 최대 3초이며 프로세스 종료 시에도 해제됩니다. 회전 정책은 전환 전에 읽은 외부·내부 값을 패널 위치가 바뀐 뒤 다시 배치합니다. 독립 복구 프로세스는 앱이나 제어 프로세스가 비정상 종료된 경우 이 값과 출력 경로를 다시 적용합니다.

앱은 화면 밝기, 자동 밝기, 화면 크기, 화면 밀도, 화면 꺼짐 시간, 절전 설정을 기록하거나 변경하지 않습니다. 현재 시험판은 시스템 출력 기록과 현재 nits가 일치하는 SDR 밝기로 복구를 준비합니다. 전환 직전 패널이 순간 OFF가 된 경우에만 최근 정상 SDR 출력을 한 번 복구하며, 이 보호는 최대 1.5초 동안만 적용합니다. 양수의 정상 밝기는 덮어쓰지 않습니다. 정지 화면의 밝기 기록은 5분이 지나도 현재 nits로 재검증하며, HDR·밝기 불일치·다른 패널 기록은 사용하지 않습니다. 유효 표본이 없으면 밝기 유지는 적용하지 않습니다. 렌더러의 밝기 곡선은 애니메이션 이미지의 픽셀 명암이며 기기의 밝기 설정과는 별개입니다.

현재 구현은 한 앱의 화면을 내부·외부 패널에 이어 보여 줍니다. 두 패널에서 서로 다른 앱을 동시에 실행하는 기능은 제공하지 않습니다. 화면 회전, 멀티 윈도우, 펌웨어 변경에 따른 시스템 내부 API 차이는 추가 검증이 필요합니다.
